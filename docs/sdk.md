# SDK

The SDK is the chain layer of kasakame, published as `@kasakame/sdk`. It holds the claim-tree math, campaign reads, and transaction assembly that the frontend and the escape-hatch CLI share. You build transaction groups in the SDK and the wallet signs them; the SDK never holds keys or funds.

Status: version `0.2.0`, published as a public npm package. The frontend and CLI consume `"@kasakame/sdk": "^0.2.0"` from the registry; a packed local copy is installed only to test unreleased SDK changes. See [`cli.md`](cli.md) for the escape-hatch CLI.

## Why the SDK exists

Before the SDK, the frontend's `lib/` folder held the chain logic: claim-tree math, indexer replay, campaign reads, and transaction assembly. That code could not leave the frontend, so the CLI and any third-party client had to reimplement proofs. The SDK moves that layer into one versioned, framework-free package. The frontend stays thin: it builds views and handles wallet approvals, while the SDK owns the protocol logic.

## Package identity and placement

- Location `projects/sdk/`. The AlgoKit workspace discovers `projects/*` entries through their `.algokit.toml`, so the SDK ships a minimal one to take part in `algokit project run` and `bootstrap`.
- One package. Split only when a consumer needs a subset; today nobody does.
- Version `0.2.0`, public package (`publishConfig.access: "public"`). Reserve the `@kasakame` npm org early (free, prevents squatting).
- Node.js >= 24, ESM. Entry point is `./dist/index.js` with types in `./dist/index.d.ts`; `files` publishes only `dist/` plus the package metadata and README.

Peer dependencies: `@algorandfoundation/algokit-utils` (`AlgorandClient` and the generated clients' runtime) and `@kasakame/constants`. Direct dependencies: `@noble/hashes` (SHA-512/256, the same function as the AVM opcode) and `algosdk` (indexer and algod access). The SDK receives the consumer's `AlgorandClient`, so `algokit-utils` is a peer; one copy keeps the class and type instances consistent.

## How to consume it

### Configure once at startup

Call `configureSdk` once with an `AlgorandClient` and the Registry and ClaimsVault app ids:

```ts
import { configureSdk } from '@kasakame/sdk'
import { AlgorandClient } from '@algorandfoundation/algokit-utils'

const algorand = AlgorandClient.fromConfig({
  algodConfig: { server, port, token },
  indexerConfig: { server, port, token },
})

configureSdk({
  algorand,
  registryAppId: 776939068n,
  vaultAppId: 776939077n,
})
```

The frontend calls this in `lib/algorand.ts` after building its client. The CLI builds its own client from flags or env (see [`cli.md`](cli.md)). Every SDK read and write uses the configured session.

### Read campaigns

```ts
import { enumerateCampaigns, getCampaign, fetchChainTimestamp } from '@kasakame/sdk'

const ids = await enumerateCampaigns()
const now = await fetchChainTimestamp()
const campaign = await getCampaign(ids.values().next().value, now)
```

### Write through the wallet

Each write takes a `WalletSession` (`{ address, signer }`) so the wallet holds the keys:

```ts
import { pledge } from '@kasakame/sdk'

await pledge(appId, { address, signer }, amountMicroAlgos)
```

### Re-exports

The frontend re-exports the SDK through `src/lib/claimtree.ts`, `src/lib/campaign.ts`, and `src/lib/transaction.ts`, so existing importers keep working while the SDK owns the logic.

## Public API surface

The barrel file `src/index.ts` exports everything below. Generated clients live in `src/generated/` (gitignored) and are regenerated from the installed `@kasakame/contracts` ARC-56 specs; do not import them directly.

### Module map

The three modules are folders, one concern per file. `src/index.ts` re-exports the same public names, so imports from `@kasakame/sdk` are unchanged.

- `src/claim-tree/` - `tree.ts` (leaves, append, root, frontier, node rows), `proof.ts` (path shape, auth paths, path and frontier blobs, base32), `fees.ts` (tree cap and OpUp iterations), `indexer.ts` (pledge and spend replay, cache), `index.ts` (barrel).
- `src/campaigns/` - `decode.ts` (global state, box names, create args), `view.ts` (status and view model), `header.ts` (live and deleted headers), `read.ts` (indexer reads, enumeration, list cache), `index.ts` (barrel).
- `src/transactions/` - `clients.ts` (session-bound generated clients), `fees.ts` (minimum fee and spend headroom), `vault.ts` (vault box and config reads, window math, address), `errors.ts` (stale-proof detection and retry), `campaign.ts` (create and register), `pledge.ts` (pledge and cancel), `settle.ts` (refund, claim, delete), `index.ts` (barrel).

### Specs version

`SPECS_VERSION` is generated by codegen from the `@kasakame/contracts`
package version (or the local contracts package version with `SDK_SPECS=local`)
and exported from the barrel:

```ts
import { SPECS_VERSION } from '@kasakame/sdk'
```

It records the contracts package version the generated clients were built
against.

### Chain plumbing (`chain.ts`)

```ts
interface SdkConfig {
  algorand: AlgorandClient
  registryAppId: bigint
  vaultAppId: bigint
}

function configureSdk(config: SdkConfig): void
function getSdkConfig(): SdkConfig
function fetchChainTimestamp(): Promise<bigint>
function waitForIndexerRound(round: bigint, timeoutMs?: number, pollMs?: number): Promise<void>
function waitForIndexerCatchUp(timeoutMs?: number, pollMs?: number): Promise<void>
```

`configureSdk` stores the session. `getSdkConfig` throws until you call it. `fetchChainTimestamp` reads the latest block header; use this, not `Date.now()`, for deadline and status decisions. The two waiters poll the indexer until it catches up to a round or to algod's tip.

### Claim-tree math and replay (`claim-tree/`)

Pure math, no network:

```ts
interface PledgeRecord {
  backer: string
  amount: bigint
  txidHex: string
}

interface TreeState {
  leaves: Uint8Array[]

}

  siblings: Uint8Array[]

  lower: Uint8Array[]
}

  position: number
  amount: bigint
  txidHex: string
}

function hashPair(left: Uint8Array, right: Uint8Array): Uint8Array
function u64be(value: bigint): Uint8Array
function u64beDecode(value: Uint8Array): bigint
function leafFor(backer: string, amount: bigint, txidHex: string): Uint8Array
function emptyTree(): TreeState
function appendLeaf(state: TreeState, pledge: PledgeRecord): TreeState
function foldPeaks(peaks: Uint8Array[]): Uint8Array
function treeFrontier(state: TreeState): Uint8Array[]
function treeRoot(state: TreeState): Uint8Array
function nullLeaf(state: TreeState, position: number, amount: bigint): TreeState
function pathShape(n: bigint, k: bigint): { r: number; c: number; hasTop: boolean }

function frontierForPledge(state: TreeState): Uint8Array
function pathBlobForRefund(state: TreeState, k: number): Uint8Array
function base32ToBytes(input: string): Uint8Array
```

Replay over the configured indexer:

```ts
interface PledgeEvent extends PledgeRecord {
  round: bigint
}

interface SpendEvent {
  position: number
}

function fetchPledges(campaignId: bigint, vaultAddress: string): Promise<PledgeEvent[]>
function fetchSpends(campaignId: bigint, vaultId: bigint): Promise<SpendEvent[]>
function loadTree(campaignId: bigint, vaultId: bigint, vaultAddress: string): Promise<TreeState>
function fetchMyLeaves(campaignId: bigint, address: string): Promise<BackerLeaf[]>
function clearTreeCache(): void
```

`loadTree` replays pledges in chain order, then nulls spent positions. `fetchMyLeaves` returns the viewer's unspent leaves, which drive refund and cancel buttons and the pledge total. The replay assumes every pledge and spend is a **top-level** block transaction; the contracts enforce that with `Global.callerApplicationId == 0`, so an app-created inner group is rejected rather than silently producing a tree the SDK cannot rebuild. The SDK's write helpers clear the replay cache internally; `clearTreeCache` is an escape hatch for an external mutation.

### Campaign reads (`campaigns/`)

```ts
type CampaignStatus = 'open' | 'successful' | 'failed'

interface CampaignViewModel {
  id: bigint
  creator: string
  title: string
  metadataUri: string
  goalMicroAlgos: bigint
  raisedMicroAlgos: bigint
  deadlineSeconds: bigint
  status: CampaignStatus
  claimed: boolean
  myPledgeMicroAlgos?: bigint
  deleted?: boolean
}

interface CampaignHeader {
  id: bigint
  creator: string
  title: string
  metadataUri: string
  goalMicroAlgos: bigint
  deadlineSeconds: bigint
  raisedMicroAlgos: bigint
  status: 'open' | 'failed' | 'claimed'
  deleted: boolean
}

function getCampaignStatus(header: CampaignHeader, nowSeconds: bigint): 'open' | 'successful' | 'failed'
function campaignFromHeader(header: CampaignHeader, nowSeconds: bigint): CampaignViewModel
function decodeGlobalState(app: algosdk.indexerModels.Application): {
  creator?: string
  title?: string
  metadataUri?: string
  goal?: bigint
  deadline?: bigint
  raised?: bigint
  status?: bigint
}
function isCampaignApp(app: algosdk.indexerModels.Application): boolean
function toCampaignViewModel(
  app: algosdk.indexerModels.Application,
  nowSeconds: bigint,
  myPledgeMicroAlgos?: bigint,
): CampaignViewModel
function fetchMyPledge(appId: bigint, address: string): Promise<bigint | undefined>
function fetchRegisteredCampaignIds(registryId: bigint): Promise<Set<bigint>>
function isRegistered(appId: bigint): Promise<boolean>
function enumerateCampaigns(): Promise<Set<bigint>>
function getCachedCampaigns(): { campaigns: CampaignViewModel[]; nowSeconds: bigint } | undefined
function setCachedCampaigns(result: { campaigns: CampaignViewModel[]; nowSeconds: bigint }): void
function clearCachedCampaigns(): void
function listCampaigns(viewerAddress?: string): Promise<{ campaigns: CampaignViewModel[]; nowSeconds: bigint }>
function getCampaign(appId: bigint, nowSeconds: bigint, viewerAddress?: string): Promise<CampaignViewModel | undefined>
function fetchCampaignHeader(appId: bigint): Promise<CampaignHeader | undefined>
```

`enumerateCampaigns` unions Registry-registered ids with vault-box ids, so deleted-but-unfinalized campaigns still surface. `getCampaignStatus` derives the display word: `successful` when claimed or goal-reached, `failed` when past the deadline and unfunded, `open` otherwise. `claimed` keeps the raw Claimed fact, so actions can tell a funded campaign awaiting claim from one already claimed (the display word is `successful` for both). For deleted campaigns, `fetchCampaignHeader` decodes the creation transaction's ARC-56 tuple and recovers the live total from the vault box; `getCampaign` recovers the same fields through it. `campaignFromHeader` maps either header to the view model (deriving the display status), so the detail view and the deleted section of the browse list agree on a deleted campaign.

### Writes (`transactions/`)

```ts
interface WalletSession {
  address: string
  signer: TransactionSigner
}

interface VaultBoxView {
  paidIn: bigint
  paidOut: bigint
  status: number
  settledAt: bigint
}

function isStaleProofError(error: unknown): boolean
function vaultAddress(): string
function fetchVaultBox(appId: bigint): Promise<VaultBoxView | undefined>
function fetchVaultConfig(): Promise<{ window: bigint; sweepTarget: string }>
function refundWindowEndsAt(settledAt: bigint, window: bigint): bigint
interface CreateCampaignResult {
  appId: bigint
  appAddress: string
  registered: boolean
  registerError?: string
}

function createCampaign(
  session: WalletSession,
  title: string,
  metadataUri: string,
  goalMicroAlgos: bigint,
  deadlineSeconds: bigint,
): Promise<CreateCampaignResult>
function registerCampaign(appId: bigint, session: WalletSession): Promise<void>
function pledge(appId: bigint, session: WalletSession, amountMicroAlgos: bigint): Promise<void>
function pledgeGroup(
  appId: bigint,
  session: WalletSession,
  amountMicroAlgos: bigint,
): Promise<TransactionWithSigner[]>
function cancelPledge(appId: bigint, session: WalletSession, leaf: BackerLeaf): Promise<void>
function refund(appId: bigint, session: WalletSession, leaf: BackerLeaf): Promise<void>
function refundGroup(appId: bigint, session: WalletSession, leaf: BackerLeaf): Promise<TransactionWithSigner[]>
function claim(appId: bigint, session: WalletSession): Promise<void>
function deleteCampaign(appId: bigint, session: WalletSession): Promise<void>
function settleOpen(appId: bigint, session: WalletSession): Promise<void>
function releaseClaimed(appId: bigint, session: WalletSession): Promise<void>
function finalize(appId: bigint, session: WalletSession): Promise<void>
```

Creation sends `create`, then registers with the Registry in a second group because registration references the app id from the creation round. If registration fails, `createCampaign` returns the app id with `registered: false` and the Registry error in `registerError`; `registerCampaign` retries without recreating the campaign, and treats an already-registered campaign as success. A stale Campaign program hash cannot be repaired by retrying: register against a Registry with the matching hash, or delete the pristine campaign with the same `[unregister, delete]` group and recreate it with the matching SDK. Pledges are one atomic group `[pay, campaign.pledge, vault.credit]` with a freshly rebuilt frontier and one stale-proof retry. The order is load-bearing: the payment must immediately precede `pledge`, the matching `credit` must immediately follow it and be last, and the vault requires that pledge immediately before the credit (both NoOp; no standalone credits/donations). Refunds route by vault box state: an open box goes through the campaign, a failed box goes straight to `vault.refund`. If the box settles or the campaign app disappears between the read and the send, the SDK re-reads the box and retries the route once; `campaign is not refundable` is a real state failure, not a routing retry. Delete groups `[unregister, delete]` atomically: the Registry requires the delete immediately after unregister, and the campaign requires the unregister immediately before it (both NoOp). An unregistered campaign's unregister no-ops, so the same group cleans up a registration that never landed. Delete settles in O(1) on every path.

`fetchVaultBox` returns `undefined` only when the box is missing. Network, auth, and server errors propagate, so a failed read cannot misroute a refund or underfund `finalize`.

`pledgeGroup` and `refundGroup` return the built, unsigned group with the session signer attached - an escape hatch for external signers or inspection that never submits. `pledge` and `refund` are the build-and-send wrappers, including the indexer waits and stale-proof retry.

`settleOpen`, `releaseClaimed`, and `finalize` are the permissionless cleanup helpers. `settleOpen` settles a failed campaign whose creator is gone while the campaign app still exists, after which refunds go through the vault. `releaseClaimed` releases a claimed campaign's vault box, recovering its minimum balance; a missing box is a no-op. `finalize` sweeps a settled-failed campaign's residual to the sweep target and releases its box once the refund window closes or the box is fully paid out; it funds the residual payment's inner fee from the vault box.

## Design decisions

- **One explicit setup call instead of singletons.** An SDK cannot depend on Vite or React, so you call `configureSdk` once at startup. The frontend passes its `AlgorandClient`; the CLI builds one from flags or env.
- **Structural, framework-free types.** `WalletSession` uses algosdk's `TransactionSigner` with no wallet dependency. Indexer and algod access go through the configured `AlgorandClient`.
- **Host-provided classes are peers.** `@algorandfoundation/algokit-utils` and
  `@kasakame/constants` are peer dependencies. The consumer creates the
  `AlgorandClient`; a second copy could mismatch types or runtime classes. The
  generated clients resolve the same peer.
- **Released interfaces are the default inputs.** The SDK builds against the installed `@kasakame/contracts` package: `scripts/codegen.ts` reads `node_modules/@kasakame/contracts/dist/arc56` and regenerates clients with its own pinned generator. `SDK_SPECS=local` reads `projects/contracts/smart_contracts/artifacts` and is the explicit override inside a change set that modifies the contracts. The published SDK ships the generated clients; building locally needs the released package installed (or `SDK_SPECS=local` after a contracts build).
- **Generated clients are build output; the ARC-56 spec is the interface.** `*Client.ts` stays gitignored; specs are read from the package (or locally) and never committed. The SDK regenerates clients from specs and tags them `// @ts-nocheck` (they do not pass the strict compiler). Clients never travel between packages.
- **The SDK returns protocol-shaped data; views stay in the frontend.** `CampaignViewModel`, messages, navigation, and disconnect handling stay in the frontend. The stale-proof retry policy moves to the SDK because the CLI needs it; the error-to-message mapping stays in the frontend.
- **Upload auth stays out.** Backend sign-in flows are backend-coupled, not chain logic.

## Conventions

Mirror the frontend: ESLint and Prettier config copies, strictest tsconfig trio, Vitest with the 100 percent line, branch, and function gate, specs colocated (`*.spec.ts`) moving with their modules. Commit scope `sdk`.

LocalNet integration lives in `test/00-open-campaign.integration.test.ts` through
`test/04-large-tree.integration.test.ts`, with shared fixtures under `test/utils/`.
`npm run test:integration` runs the numbered files in path order against a live
LocalNet; the suite is excluded from `npm test` and coverage. Each file deploys
its own Registry + ClaimsVault from the generated clients' ARC-56 bytecode and
runs one lifecycle or scale scenario. The file and tag map is in
[`testing.md`](testing.md#sdk-localnet-integration). The clients decide which
contracts are under test: the installed contracts package by default, or the
local artifacts after `SDK_SPECS=local npm run codegen`.

## Release info

- Version `0.2.0`, following the contracts' breaking changes while they churn.
- Public npm package, published as `0.2.0`. The frontend and CLI consume
  `"@kasakame/sdk": "^0.2.0"` from the registry.
- Release `@kasakame/contracts` and `@kasakame/constants` first: the SDK builds
  from the released contracts package and declares constants as a peer
  dependency.
- License: MIT (`package.json` SPDX id and a `projects/sdk/LICENSE` copy); the published tarball includes it.
- Packaging: `files: ["dist"]`, `publishConfig.access: "public"`, `projects/sdk/README.md`, and the MIT `LICENSE`. The manual `release-sdk` workflow takes the package version (checked against `package.json`), defaults to `dry_run=true`, runs codegen, build, lint, format, type-check, coverage, `npm pack --dry-run`, a dry-run publish, and a tarball install/import smoke test as separate steps, and only publishes with `dry_run=false`; releases authenticate with npm OIDC trusted publishing and pass `--provenance`.
- Source maps: `tsconfig.build.json` sets `inlineSources: true` and `declarationMap: false`. The `dist/*.js.map` files carry the TypeScript source text and no `.d.ts.map` files ship, so the `dist`-only tarball can still be stepped through in a debugger. The packed-tarball smoke test checks both.
- Release gate: the `release-sdk` workflow runs the SDK LocalNet suite in an `integration` job before publishing, against the prep-generated clients and the tested `dist`. A failure stops the publish.
- The registry version is the committed default. To test unreleased contracts/SDK changes, build the SDK (`npm run build` in `projects/sdk`) and install it as a packed local copy (`npm install --no-save --install-links "file:../sdk"` in `projects/frontend`); a plain `npm ci` restores the published package.
- Codegen: `npm run codegen` (also the `prebuild` hook) reads the installed `@kasakame/contracts` package (`node_modules/@kasakame/contracts/dist/arc56`) and regenerates each `*Client.ts` from its ARC-56 spec with the pinned `@algorandfoundation/algokit-client-generator`, tagged `// @ts-nocheck`. Install the released package with `npm install --no-save --no-package-lock @kasakame/contracts@<version>` (use the version in `projects/contracts/package.json`), or set `SDK_SPECS=local` to use `projects/contracts/smart_contracts/artifacts`; the version comes from the contracts package and is exported as `SPECS_VERSION`.
- Build: `npm run build` (`tsc` to `dist/`). The default codegen needs `@kasakame/contracts` installed; `SDK_SPECS=local` needs a contracts build instead.
